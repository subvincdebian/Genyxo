# Стилі та межі FSD

`src/fsd/shared/styles` містить окремі перенесені таблиці стилів:

| Файл            | Оригінал                       |
| --------------- | ------------------------------ |
| `style.css`     | `public/style.css`             |
| `chat.css`      | `public/chat.css`              |
| `profile.css`   | `public/profile.css`           |
| `dashboard.css` | `public/dashboard.css`         |
| `policies.css`  | `public/policies/policies.css` |

Сторінка імпортує лише свої таблиці стилів у початковому порядку. Не імпортуйте всі п'ять файлів у кореневий layout: однакові селектори сторінок можуть перекривати один одного. Це звичайні CSS-файли, тому їхні селектори залишаються глобальними в межах завантаженого документа.

Tailwind CSS 4 підключено через `tailwind.css`: тільки `theme.css` та `utilities.css`, без Preflight. Префікс `gx` поширюється на утиліти й змінні теми. Новий utility-клас має вигляд `gx:flex`; існуючі `.hidden`, `.show` та інші legacy-класи не стають Tailwind-класами.

Кожна таблиця стилів використовує `@reference './tailwind.css'`, щоб `@apply gx:flex` та інші утиліти розгорталися локально. Замінено тільки буквальні декларації з еквівалентним CSS-результатом. Кожне `@apply` стоїть на місці початкової декларації: групування не змінює порядок повторних правил і властивостей. Розміри, одиниці, кольори, URL, селектори, медіазапити та `!important` залишаються початковими. Декларації всередині `@keyframes` не перетворюються. `user-select` залишено звичайним CSS, оскільки відповідна Tailwind-утиліта додає зайву vendor-декларацію.

Конфліктні назви legacy-анімацій отримали префікс `genyxo-`: `spin`, `bounce` та `pulse` у відповідних `@keyframes` і деклараціях `animation`. Tailwind 4.3.3 може додати свої default keyframes навіть через `@reference`, коли legacy CSS використовує ці назви; доданий наприкінці default keyframe змінює початкову анімацію. Нові назви зберігають кадри й параметри початкових анімацій та не конфліктують з Tailwind `animate-*`.

`npm run lint` також запускає `scripts/check-architecture.mjs`. Він читає TypeScript-конфігурацію та перевіряє реальні статичні `import`, `export ... from`, `import ... = require`, `require` і `import()` у JS/TS-файлах `src` та `app`. Дозволений напрям між різними шарами: `app → pages → widgets → features → entities → shared`. Імпорти в межах одного шару дозволено; `src` не може імпортувати App Router entry points. App Router може компонувати модулі шарів. Невідомі шари та обчислювані module imports завершують перевірку помилкою.

Ця перевірка не перевіряє публічні API slice, бізнес-відповідальність компонентів, CSS-імпорти чи ресурси `public`. Зовнішні пакети не належать до FSD-шарів. Існування й типову сумісність модулів додатково перевіряє `npm run typecheck`.

Для перевірки міграції компілюйте кожну таблицю через поточний PostCSS pipeline та порівнюйте порядок селекторів, вкладених at-rules, декларацій, їхні значення й `!important` з оригіналом, враховуючи лише описане перейменування animation names. Це перевіряє CSS-контракт; завантаження правильних файлів і поведінку React-сторінок потрібно перевіряти окремо в браузері.
