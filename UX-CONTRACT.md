# Workspace interaction contract

## Account settings extension

`/profile` uses hash-linked sections and explicit saves for profile and personalization. Unsaved edits prompt before leaving; failed requests preserve drafts and provide retry. A pending save blocks section navigation. Avatar uploads are validated, centre-cropped and compressed locally before persistence. Email remains a verified sign-in identity; changes go through Support. Unsupported card management, device inventories, MFA and passkeys are never simulated.

Profile identity, balances, referral links and ledger pages come from authenticated owner-scoped APIs. The transaction filter is server-side with bounded pagination; usage aggregates approved SPEND entries into 7/30/90 UTC days and exports those same rows to CSV. No extrapolated percentages or synthetic graph points are displayed. Zero-cost requests remain visible as requests. Ledger precision is decimal; previously truncated amounts cannot be reconstructed.

Password changes verify the current credential, reject bcrypt-equivalent credentials and revoke every session. Revocation versions are stored in MySQL and checked on the primary on each HTTP authentication and socket connection. Existing notification sockets disconnect when sessions are revoked. The app confirms sign-out; successful password changes and global sign-out return to sign-in. Personal instructions and response language use the workspace preference record and enter chat context independently of memory.

Verification: `tests-profile/account.spec.ts` uses a disposable account and real local MySQL/Mailpit, covers reload persistence, offline save recovery, filtered pagination, fractional usage, reduced motion, mobile fit, language/theme selection, and session revocation. `scripts/verify-profile-migration.ts` proves preservation against isolated MySQL tables and blocks a lossy rollback.

Scope: `/chat`, `/library`, `/plugins`, `/scheduled`. Existing marketing/authentication have their own maintained behavior. The shared workspace layout preserves sidebar DOM, scroll and composer drafts across section navigation.

## Persistent and transient state

Server: conversation metadata, preferences, project files/instructions, explicit memories, library, preset versions and encrypted private connection configuration. Local per-user storage: expanded project IDs. Local presentation storage: collapsed width. Composer draft and scroll live in the mounted workspace. New chat creates no server row before first send. Network retries reuse a request key. A processing request linked to a conversation reconnects instead of recharging.

## Accessibility and motion

Dialog uses native focus containment, Escape, focus return and a reference-counted body scroll lock. Mobile drawer makes background inert and restores focus/overflow. Menu supports arrows, Home/End and Escape. Rename supports F2, Enter, blur and Escape. Search supports Ctrl/Cmd+K, arrows and IME composition. Desktop collapse is Ctrl/Cmd+Shift+S. Reduced motion disables decorative transitions; keyboard focus remains visible. Skeletons preserve loading geometry.

## Honest availability

Sharing is visibly planned. Unconfigured scheduled execution and external plugin adapters expose their actual availability; storing API configuration never claims that a provider is connected. No simulated AI responses or unconditional success states. Real provider/DB integration must be verified in a configured test environment before release.

## Workspace control follow-up

`WorkspaceIcon`, `WorkspaceMenu` and `WorkspaceTooltip` in `shared/ui/workspace.tsx` own icons, menu positioning/toggling and tooltips for all workspace screens. SVG geometry is served from the local sprite; source provenance is recorded beside it. Hover motion is local CSS, active only under a fine hovering pointer, with a 0.64s sequence followed by rest until the next 8s cycle. Reduced motion suppresses animation. Menus ignore trigger pointerdown and consume the subsequent trigger click before React can reopen them; Escape restores focus. Overview prefers the right side and falls back inside narrow viewports. Tooltips are attached to the actual control through aria-describedby, remain mounted for 140ms exit, clamp using measured dimensions, dismiss on scroll/resize/Escape and never overlay an expanded trigger menu. Verification: workspace-controls.spec.ts plus the existing workspace browser suite.

## Canvas

`widgets/canvas` owns the side panel that previews and edits code and documents. Any code opens it by dispatching `genyxo:canvas-open` with `{ content, language, title? }` (`openCanvas` in React). The chat controller adds "Open in canvas" to code blocks and to the answer menu, and attaches a card plus an automatic open for a finished answer whose largest HTML, SVG or React block has at least 12 lines.

HTML, SVG, CSS, JavaScript and React (JSX/TSX via React 18 UMD and Babel standalone from jsDelivr) render in an `iframe` sandboxed with `allow-scripts allow-forms allow-modals` and without `allow-same-origin`, so preview code cannot read the session token. Console output and runtime errors are forwarded by `postMessage` and accepted only from that frame. Markdown renders with `marked` and DOMPurify. Edits stay in the panel until "Save to Library", which creates a document once and updates the same item afterwards. The panel resizes by pointer (360px to 72% of the viewport, stored per browser), expands to full width, closes with Escape and closes on New chat. Below 1024px it overlays the chat; below 768px it is a full-screen sheet. Verification: Playwright script with a mocked `/chat/stream` covering auto-open, live React render, edit, console, Escape and the document view at 1440px and 390px.

## Composer add menu and voice

`widgets/chat/ui/ComposerPlusMenu.tsx` replaces the legacy attachment popover in the workspace. Uploads, camera photos (touch devices), Library items and sketches (`SketchDialog`) all enter the controller's existing pipeline by setting `#fileInput.files` and dispatching `change`, so limits and previews stay in one place. Model shortcuts change `#modelSelect`; projects use `setActiveProjectId`; skills dispatch `genyxo:workspace-preset`. The menu filters as you type (search field focused on fine pointers only) and drills into Library, Project and Skill pages; Backspace returns to the root.

Voice conversation (`widgets/chat/model/voice-session.ts`, `VoiceMode.tsx`) needs a signed-in account; guests get a sign-in notice. The microphone (echo cancellation, noise suppression, auto gain, plus a ×1.8 input gain) feeds a MediaRecorder and a level meter; voice-activity detection ends a phrase after 0.9 s of silence. `POST /api/chat/voice/transcribe` sends the phrase to Gemini (`VOICE_TRANSCRIBE_MODEL`, default `gemini-3.5-flash-lite`), which returns the text in the spoken language plus its BCP-47 code — any language, Ukrainian included. The text is submitted through `#chatForm`; streamed reply sentences go to `POST /api/chat/voice/speak` (`VOICE_TTS_MODEL`, default `gemini-3.8-flash-lite-tts`, voice `VOICE_TTS_VOICE`) with that language and play in order, the first sentence alone for a fast start; browser speech is the fallback. The stage shows the detected language. Tapping the orb interrupts playback and generation; Mute disables the track and recording; End releases the microphone and audio graph. Verification: `chat-features.spec.ts` (fake microphone, mocked endpoints) and a live run that fed a Ukrainian WAV as the microphone.

## Failed answers

When the model fails before answering, `ChatService.rollbackFailedTurn` deletes the saved question and, if the request created the chat, the chat itself; the SSE error event carries `rolledBack` and `conversationId` (`null` when the chat was removed). The client keeps the question bubble, shows an inline error with a plain-language reason, **Retry** (re-sends the same text and files) and **Edit** (returns them to the composer), and clears the URL id when the chat was removed. Credits are refunded as before. A stream the user stops is not rolled back. Verification: `chat.service.spec.ts` rollback cases, `chat-features.spec.ts` failure/Retry/Edit, and the live failing-model test.

## Submenus

Nested choices use `WorkspaceSubmenu` (shared/ui/workspace.tsx): a menu item that opens a glass flyout beside itself on hover (70 ms intent delay), focus (→, Enter, Space) or tap, flipping to the left when the right edge has no room. While the pointer travels from the item toward the flyout it stays open inside the "safe triangle" (exit point to the flyout's near edge); leaving that triangle closes it after 90 ms. ← and Escape close the flyout and return focus to its item; keys inside the flyout never reach the parent menu. Flyouts are portalled and marked `data-ws-submenu`, which the parent menu treats as inside. No menu uses a "back" row. `WorkspaceMenu` placement `auto` opens below when the content fits, otherwise above, otherwise on the roomier side with a capped height; `positionTarget` lets the add menu sit against the whole composer. The model picker closes with an exit animation after a choice and expands provider groups in place with a height animation.

Dictation (the composer microphone) uses the same `POST /api/chat/voice/transcribe` for signed-in users: click to record (×1.8 input gain, 2-minute cap), click again to stop; the button shows a breathing ring while recording and a spinner while Gemini transcribes, then the text is appended to the draft in the language spoken. Guests are asked to sign in.

Reply language: every chat turn carries a system instruction to answer in the language of the user's latest message. When that message is too short to tell ("hi", "ok", code only), the answer uses the user's usual language: what their earlier prompts were written in counts most, then the country from the CDN header (`cf-ipcountry` and similar; absent on localhost), then `navigator.languages`. Voice transcription gets the same hints plus the language the call has been in, so close languages (Ukrainian, Russian, Slovak, Polish) are not confused; Cyrillic transcripts are never labelled with a Latin-script language.

Voice turns are sent with `voice: true` and the spoken `language`: replies are short and conversational (one sentence for greetings), skip markdown, and start without extended reasoning. When the user asks for code or a file in a call, the assistant says one sentence, the file appears in the chat, and the voice says "I've put the file in the chat" in the spoken language instead of reading the code.

Voice calls run on Gemini Live: the browser gets a single-use token from `POST /api/chat/voice/live` (model, voice, instructions, language hints, recent chat turns and the `create_file` tool are fixed in the token, so the API key never leaves the server) and streams the microphone to Gemini as 16 kHz PCM over a WebSocket; the reply streams back as 24 kHz audio and starts about a second after the user stops talking. Gemini detects the end of speech and handles barge-in; while the model talks, quiet input is sent as silence so its own echo does not interrupt it. The reply's transcript streams into a chat bubble, files the model makes through `create_file` appear as file cards, and each finished exchange is saved with `POST /api/chat/voice/turn` (creating the chat on the first turn). If Live cannot start, the call falls back to record → transcribe → chat → speech.

Voice stage: the orb, a quiet uppercase status line (Listening, Thinking, Speaking, Microphone muted) and one caption that crossfades; no pills. The call controls hold a voice picker: a glass menu of Gemini's prebuilt voices (eight featured, the rest under "More voices"), each with a tone, a gradient mark and a preview button; the header says which language replies use. The choice is saved per browser (`genyxo.voice`) and sent with every speech request. Free Gemini keys allow few speech requests a day: the server tries the next TTS model when one hits its quota, and once all are used up the browser's best natural voice speaks immediately for ten minutes instead of waiting on the server.

Files: a fence labelled ```lang file=name.ext renders as a file card (type tile, name, kind · lines · size) with Open (canvas), Show code (folds open), Download (saved under its own name) and Copy. Consecutive files share one bordered list.

## Plugins and connectors

`/plugins` follows ChatGPT's catalog: Plugins / Skills tabs, a settings gear (Installed view) and an **Add** menu (browse, custom API), a title and subtitle, a full-width pill search, **Installed ›** (square brand tiles linking to each plugin; empty state "Your connected apps will appear here."), a Public / Personal segmented control, then category sections — Popular, New & noteworthy, Small business, Developer tools, Productivity, Communication, Design & media, Finance & crypto, Music & play — each a two-column list of rows (brand tile, name, one-line description, action). A heading's › opens the category page (`?category=`) with breadcrumbs "Plugins › Popular"; `?view=installed` lists connected plugins. Search filters across all plugins. One column below 760px.

Row actions: the row opens the plugin page. **+** connects (sign-in redirect for OAuth and MCP plugins, instant for no-account plugins, the plugin page's key form for key plugins). **⋯** on a connected plugin opens a glass `WorkspaceMenu`: Try now (new chat with the plugin's first example prompt in the composer, never auto-sent), Manage (settings page) and red Delete (confirm, then disconnect). **ⓘ** marks plugins that cannot connect here: "Not configured" (server credentials missing) or "No public API" (Shazam); nothing fails on click.

Plugin page (`/plugins/<id>`): breadcrumbs "Plugins › Name", a 72px tile, name, "By Genyxo • description", status, ⋯ (plugin settings, website, disconnect), Manage and a primary pill (Connect / Try in chat / Reconnect / disabled reason). Below: a tinted, slowly drifting gradient banner with three plugin-specific example prompts as dark glass cards (click = new chat with that prompt), the plugin's own text, the key form for key plugins (`#connect`, every field, docs link, checked with the provider before saving), "Apps N", what Genyxo can do and the permissions requested.

Settings page (`/plugins/<id>/settings`): breadcrumbs "Plugin settings › Name" (back to the Installed view), View details (back to the plugin page) and a red Remove. **Allow** chooses when Genyxo asks: "Always ask" (default) or "Allow low-risk actions" (drafts and actions the provider marks non-destructive run without a card; sending, paying, publishing and deleting still ask). Connected accounts (account, Primary, ⋯ Reconnect / Disconnect), Uses (the plugin's apps), Tools (the provider's live MCP tool list, each marked Read-only or Asks first) and Data: connected date, category, developer, version, website, privacy policy, terms, authorization supported and used.

Connector rules (`apps/backend/src/integrations`):

- Kinds: official remote **MCP** servers with OAuth 2.1 + PKCE + RFC 8707 resource and automatic client registration (21 plugins; Genyxo registers once per authorization server and stores the client in `integration_clients`), Genyxo **OAuth apps** (Google, Microsoft, GitHub, Zoom, Spotify, LinkedIn), user **keys** (Render, Shopify, MongoDB Atlas service account, Tripo), **no account** (public data, skills, open MCP) and **unavailable**. Nothing pretends: a plugin without an API is labelled, never simulated.
- One `integration_connections` row per user and plugin; tokens, refresh tokens and key fields are AES-256-GCM ciphertext (`INTEGRATIONS_ENCRYPTION_KEY`, falling back to `WORKSPACE_ENCRYPTION_KEY`) and never leave the server.
- OAuth: the `state` is sealed with the same key (user, plugin, PKCE verifier, MCP token endpoint, 10-minute expiry) and its nonce must match an HttpOnly `SameSite=Lax` cookie, so a callback only completes in the browser that started it. Success lands on the plugin page (`?connected=1`), failure on `/plugins?integrationError=<code>`. Tokens refresh a minute before expiry and once more after a 401; a dead refresh token marks the plugin "Reconnect".
- Disconnect revokes the grant where the provider supports it (MCP revocation endpoints, GitHub, Google, Zoom, LinkedIn) and always deletes the stored tokens.
- Chat (`ChatService.processStreamingMessage`): only the user's connected plugins are offered — Gemini as function declarations (MCP schemas reduced to Gemini's subset), OpenRouter as OpenAI `tools` (models without tool support answer without them). MCP plugins expose the provider's own tools; REST plugins add curated tools plus a raw API tool (`<plugin>_api_request` or `_graphql`) whose path must stay inside the provider's API. Over 110 tools, large MCP plugins switch to `find_tools` / `run_tool`. The loop runs at most 6 steps and streams each as an activity ("Linear · Create issue"). Skill plugins (Superpowers, Xmind) add instructions instead of tools. Voice turns get no tools.
- Writes (MCP tools without `readOnlyHint`, raw non-GET calls, GraphQL mutations, curated write tools) never run from the model unless the plugin's policy allows that low-risk tool. Otherwise the call stores an `integration_actions` row with the exact arguments and streams a ```genyxo-action fence; the chat renders it as a card with recipients, targets and body, plus Confirm / Cancel. Confirm claims the row atomically (no double run), rebuilds MCP tools from the provider's list, runs with the user's token and rewrites the card in the stored message to Done / Failed / Cancelled; later turns see a one-line summary. Pending actions expire after 24 hours.

Verification: `integrations.service.spec.ts` (kinds, OAuth, MCP discovery and registration, keys, policy, revoke), `integration-tools.service.spec.ts` (MCP tools, policy, raw API guard, meta tools, confirm), `chat-tools.spec.ts` (Gemini and OpenRouter loops), `workspace-plugins.spec.ts` (catalog, plugin page, settings page, key form, confirm card, phone width, light theme).

## Generated media

Every text model gets built-in tools (`apps/backend/src/chat/media`): `genyxo_generate_image` (also edits the user's attached images), `genyxo_generate_video`, `genyxo_generate_speech` and `genyxo_generate_music`, offered only when the server can make that kind and never in voice turns. The model writes an English prompt; `MediaService` calls Gemini first (`MEDIA_IMAGE_MODEL`, `MEDIA_MUSIC_MODEL`, Gemini TTS) and falls back to the same Google models on fal.ai (Nano Banana, Lyria 2, Veo 3.1 Fast via `MEDIA_VIDEO_MODEL`) when the key answers 403/404/429. Credits: image 40, video 400 (refunded when the job fails or a restart orphans it), music 60, speech free; balance is checked before any provider call.

Files are stored in `generated_media` and served from `/api/chat/media/<uuid>` (the random id is the capability, so `<img>`/`<audio>`/`<video>` load without a token; only image/audio/video types are served inline, with `nosniff` and a sandbox CSP). Images appear inline as Markdown; audio and video arrive as a ```genyxo-media fence rendered as a card with a player and Download. Videos start as "Rendering video…" and the card polls `/status` every 6 s until the background job finishes. Later turns see "[Generated video: …]" instead of the card markup. Activity steps read "Generating image", "Generating video", etc.

Verification: `media.service.spec.ts` (Gemini, fal fallback, credits, PCM→WAV, video refund, tool markdown), `chat-media.spec.ts` (inline image, audio card, pending→ready video); live run produced an image, speech, a 30 s music clip and an 8 s video through the default model.

## Library

`pages/workspace/ui/library-page.tsx` follows ChatGPT's library. Finished generated media (image, video, music, speech) is indexed into `chat_library_items` the first time the library is listed (`WorkspaceService.indexGeneratedMedia`). The item keeps the prompt in `content` and the source chat in `conversationId`. Deleting it hides it from the library through a `library-hidden` record, so it is not re-indexed; the chat that made it keeps the file. Library types are document, image, video and audio; uploads accept the same kinds (5 MB).

The header has a filter menu (type and sort), grid/list switch, search pill and a Create menu. Tabs are pills. The grid is a masonry of round-robin columns, so the newest items run along the first row. Tiles have no chrome; favorite and actions appear on hover or focus, and always on touch.

Opening an item shows a full-screen modal viewer:

- the kind pill opens a menu: source chat, rename, move, delete;
- zoom (Fit or 25–200 %), Download, Share (system share sheet, otherwise copies the link; the media link itself grants access), close;
- previous/next arrows and ←/→ keys;
- a dock: Edit, Variation and Animate for images, Favorite, Copy prompt.

"Ask about this file" starts a new chat with the file attached through `genyxo:composer-draft` (`detail.files`). It sends only because the person typed the question there; the dock actions only fill the composer. Closing returns focus to the tile of the item last shown.

Verification: `workspace.service.spec.ts` (index once, hidden after delete), `workspace.controller.spec.ts`, `library-viewer.spec.ts` (masonry order, viewer controls, zoom, favorite, keyboard, focus return, ask-with-attachment, phone fit), `workspace-pages.spec.ts`.

## Active account sessions

Authenticated HTTP requests and notification handshakes register the SHA-256 token identifier, expiry, JWT issue time, device user agent and server-observed address. Raw bearer tokens are never stored. Every token check reads individual revocation from the primary database; the account session version still provides bulk revocation. Login JWTs have unique jti values, including logins in the same second. Session listing and revocation always scope by the authenticated owner. Single-session revocation disconnects that session's sockets; global revocation disconnects the account room. Current-device sign-out also revokes its token before clearing the browser cache (local cleanup still occurs if the network fails). Older tokens are registered lazily on their next authenticated request, so unavailable historic device data is never invented.

The security screen opens a dedicated active-session view with a back action and keyboard-accessible controls. Current sessions are identified explicitly; other devices can be signed out independently.

## Appearance and settings navigation

The settings rail persists its collapsed state in this browser; every icon remains named for assistive technology and gains a tooltip. Ctrl/Cmd+K expands the rail and focuses search. Additional settings start collapsed; hidden controls are inert. Reset only clears the additional settings, preserving the chosen palette. Short exclusive choices use keyboard-operable segmented radios. System mode follows live OS changes. Circular theme reveals are interruptible and skipped for reduced motion or browsers without View Transitions; color editing stays immediate. Theme codes are validated as data, never executed; unsafe font/color values and unknown version prefixes are rejected. Imports preserve supported palette, semantic color and font metadata. Dialog Escape, focus return, toast expiry and dismissal remain available.
