## Цель и исходные требования

Пользователь хочет полностью рабочий сайдбар с удобством показанных экранов ChatGPT: проекты, их файлы, история и память, доступные при выборе разных моделей. Взаимодействия должны ощущаться плавными и премиальными. Скриншоты служат визуальными примерами, а не инструкциями из внешнего документа. Внутреннее устройство ChatGPT неизвестно; проект описывает собственную реализацию Genyxo.

Критерий результата: пользователь создаёт проект, добавляет инструкции и файлы, ведёт несколько разговоров, сохраняет важные факты, меняет текстовую модель и получает ответ с корректным контекстом выбранного проекта. История и настройки сохраняются после перезагрузки и входа с другого устройства.

## Что обнаружено в текущем коде

- Web: Next.js/React, FSD. Оболочка — `apps/web/src/fsd/widgets/chat/ui/ChatApp.tsx`; совместимый DOM-контроллер — `apps/web/src/fsd/features/conversation/model/chat.js`.
- Backend: NestJS, TypeORM, MySQL. `ChatProject` уже содержит владельца, название, инструкции и JSON файлов; `Conversation` содержит `projectId`, сводку истории и курсор сводки.
- Есть API создания, изменения и удаления проектов, переноса разговора в проект, библиотеки, переименования и удаления разговора.
- `prepareConversationContext` объединяет сводку разговора с проектными инструкциями и извлечённым текстом файлов. Есть отдельные пути потоковых, обычных и альтернативных ответов; каждый нужно проверить.
- Меню недавних чатов содержит переименование и удаление. Полей закрепления и архива в сущности разговора нет. Проектные чаты рисуются отдельным упрощённым способом.
- `renameChat` сейчас использует `showModal` с полем названия; это поведение заменяется редактированием самой строки. `startNewChat` уже сбрасывает выбранный разговор локально без запроса создания, а backend создаёт разговор через `getOrCreateConversation` при отправке сообщения. Нужно сохранить этот принцип и явно очистить composer/вложения.
- Первичное название в `getOrCreateConversation` сейчас обрезает `firstMessage` до 30 символов; фоновой генерации названия в изученном пути нет. В `ChatApp` уже есть `header-actions` с балансом и пользовательским меню: account-контролы принадлежат верхнему правому углу, а не footer сайдбара.
- В `features/chat/model/chat-inline4.js` есть контроллер модального поиска, копирующий строки из DOM истории и фильтрующий их текст. Это ограниченный старый механизм, а не проверенная реализация Spotlight; он заменяется общим владельцем Command Palette с серверными результатами.
- Кнопка `projectsBtn` уже стоит справа в `sidebar-projects-header`, но открывает общий `openProjectsPanel`. В новом поведении она остаётся в этой точке и сразу открывает создание проекта, без промежуточного каталога. Готового отдельного backend-модуля skills/presets при текущем поиске не обнаружено: вкладка «Навички» требует собственного persistence и подключения к общему контексту.
- Сейчас Library открывает модальную панель через `openLibraryPanel`; маршрута `apps/web/app/library/page.tsx` нет. Текущую панель нужно заменить полноценным экраном `/library`.
- Список разговоров ограничен первыми 100, проектов — первыми 50. Это не полноценный поиск по всей истории.
- Файлы проекта передаются как ограниченные фрагменты текста: общий предел около 12 000 символов. Нельзя показывать это как прочтение всех файлов целиком.
- Редактор заявляет PDF, DOCX и текст. Серверный нормализатор, изученный при подготовке, извлекает PDF и поддерживаемый текст, но отдельного DOCX-парсера не содержит. Поддержку DOCX нужно реализовать и проверить до её обещания в UI.
- Существующие тесты проверяют базовый проектный контекст и браузерный сценарий с подменённым API. Они не доказывают работу реальной БД или внешних моделей.
- В рабочей копии уже много изменённых и новых файлов. Они остаются исходной работой пользователя; запрещено перезаписывать их массовым откатом или включать посторонние изменения в коммит этой задачи.

## Варианты

1. **Рекомендуется: развить существующий workspace.** Сохранить transport, оплату, renderer ответов и текущие сущности; выделить владельцев сайдбара, файлов и контекста. Это обеспечивает функциональный результат без параллельной реализации чата.
2. Полностью переписать экран и контроллер чата. Даёт больше свободы, но расширяет риск регрессий стриминга, вложений, авторизации и списания кредитов. Для этой задачи не рекомендуется.
3. Сначала заменить только внешний вид. Быстрее визуально, но не выполняет требование о рабочей памяти, файлах и переносимости контекста. Не рекомендуется.

Следующие решения — предлагаемые значения по умолчанию, которые пользователь может поправить при проверке этого документа.

## Сайдбар и навигация

На desktop ширина открытого сайдбара около 280 px, компактного — около 64 px. Узкий экран получает выдвижную панель с затемнением фона. Точные размеры сверяются с текущей оболочкой, длинными названиями и zoom.

Шапка имеет две отдельные строки:

1. Слева логотип и название Genyxo; справа две компактные иконки: поиск с подсказкой `Ctrl+K` / `⌘K`, затем сворачивание панели. Порядок не меняется из-за ширины названия.
2. Широкая кнопка-плашка «+ Новий чат» на всю доступную ширину с одинаковыми боковыми отступами. Поиск, архив и другие иконки не занимают часть этой строки.

Далее вертикально расположены «Заплановано», «Бібліотека», «Плагіни», «Огляд», затем проекты, отдельный блок «Закріплені» и календарный список «Нещодавні». Здесь приведены украинские подписи из референса; runtime использует выбранную локаль. Область списков прокручивается независимо.

В правом верхнем углу страницы остаётся единственный account-блок: аватар, баланс и тариф пользователя, с существующим пользовательским меню. Он принадлежит общей шапке workspace и сохраняется на `/chat`, `/library`, `/scheduled` и `/plugins`; в sidebar эти сведения не дублируются. На narrow viewport account-блок компактно адаптируется в шапке, сохраняя доступ к балансу/тарифу через тот же контрол.

Внизу раскрытого сайдбара закреплена только минималистичная кнопка **«≡ Меню»**. Она открывает поповер вверх, над кнопкой, с существующими служебными действиями: история действий, тема (системная/тёмная/светлая), помощь, обратная связь, справочные/правовые страницы; здесь же доступен предусмотренный дизайном архив. Существующий перечень и реальные обработчики сверяются при реализации, устаревшие ссылки ведут на действующие маршруты приложения. Footer не содержит аватар, email, баланс или тариф и не превращается в карточку профиля. Поповер использует общий Menu/glass primitive, закрывается Escape/кликом вне, возвращает focus кнопке; подменю темы учитывает верхнее размещение и края экрана. Кнопка остаётся доступной при прокрутке длинной истории.

Каждый проект раскрывает свои чаты. Выбор проекта открывает обзор с файлами, инструкциями, памятью и разговорами. Создание нового чата из проекта сохраняет его `projectId`; обычный новый чат вне проекта не наследует случайно предыдущий проект. Активный проект виден возле composer.

В заголовке раздела **«Проєкти» справа всегда есть отдельная кнопка `+`** с tooltip/accessible name «Создать проект». Она доступна при пустом списке и при свёрнутом содержимом раздела. Нажатие сразу открывает общий диалог создания проекта с названием, базовыми файлами и инструкциями; не требует сначала открывать меню чата или overview всех проектов и не переключает accordion. Название обязательно, файлы/инструкции опциональны. Проверка полей, upload/error/progress и busy-состояние используют общие primitives. «Создать» сохраняет проект и переводит к его обзору; отмена не оставляет пустой проект или привязанные к нему временные uploads. После сохранения новый проект виден и раскрыт в sidebar. Создание из других точек входа использует тот же диалог, с дополнительным переносом чата только при явно выбранном действии.

### Новый чат: мгновенное переключение и ленивое создание

Широкая кнопка, карандаш над историей, иконка компактной панели, shortcut и команда Spotlight используют одно действие `startNewChat`. Оно синхронно сбрасывает выбранный ID, сообщения на экране, текст composer, вложения, локальные ошибки и выделение истории; переводит URL в `/chat` и ставит focus в composer. Объектные URL вложений освобождаются. Это клиентский переход без ожидания сети или завершения анимации: требование «0 мс» означает отсутствие сетевого ожидания и искусственной задержки, с отрисовкой на ближайшем кадре.

Обычный новый чат сбрасывает проект. Действие «Новый чат» внутри проекта выполняет тот же локальный переход, но сохраняет явно выбранный проект как область будущего первого сообщения. Сам клик не вызывает POST создания разговора, upload, генерацию или списание кредитов и не добавляет пустую строку в историю. Повторные клики также не создают записей в БД.

Разговор создаётся сервером только после явной отправки первого допустимого промпта или поддерживаемого сообщения с вложениями. Отправка, создание разговора и сохранение первого сообщения согласованы: ошибка валидации не оставляет пустой разговор. Один ключ идемпотентности первой отправки защищает от дубля при повторе запроса; блокировка кнопки на клиенте дополняет серверную проверку. ID приходит в существующем ответе/SSE и привязывается к тому черновику, который отправил запрос; URL и история обновляются один раз.

Если пользователь начал новый чат во время ответа в старом, поздние события старого запроса не возвращают старый ID в URL и не вставляют его токены в новый composer/экран. Существующий механизм остановки запроса сохраняет свою семантику оплаты; новый чат сам по себе не запускает повторную генерацию. При ошибке первой отправки сохраняются текст и вложения для повтора, а не создаётся второй пустой чат.

### Автоматическое название после первого ответа

После первой отправки строка разговора появляется с временной локализованной подписью «Новый чат»; сырой prompt и его первые 30 символов не используются как окончательное название. После сохранения первого успешного основного ответа frontend отправляет лёгкий идемпотентный `POST /chat/conversations/:id/title-generation`. Запрос передаёт ID разговора и ожидаемую версию названия, а не содержимое истории: сервер сам проверяет владельца и читает сохранённую первую пару сообщений. Альтернативный ответ, ошибка провайдера и повтор события `done` не создают новую задачу.

Backend регистрирует операцию и отвечает `202` без ожидания title-модели. Генератор получает ограниченный текст первой пары, без скрытой памяти проекта, полного содержимого файлов и base64-вложений; названия файлов допускаются только если нужны для темы. Для первого медиаответа используется текст запроса/метаданные результата. Настраиваемая лёгкая текстовая модель возвращает одно понятное название из 3–5 слов на языке диалога, без кавычек, Markdown и пояснений; сервер очищает и валидирует результат по лимиту заголовка. Это служебный расход платформы, без второго списания пользовательских кредитов и без влияния на скорость первого ответа.

Статус операции сохраняется в БД и исполняется надёжным worker/эквивалентом поддерживаемого runtime; невызванный после закрытия вкладки endpoint может быть восстановлен по сохранённому первому ответу. Не использовать необработанный `void promise` в процессе запроса как единственную гарантию. По завершении сохраняются название и версия, инвалидируется кеш и отправляется событие `conversation.updated` в существующий авторизованный канал пользователя. Список/история возвращают тот же статус при reconnect/reload; пока операция pending, допустим ограниченный polling с backoff, который останавливается при завершении/unmount.

Обновление бесшовно заменяет текст только нужной строки во всех представлениях, без перерисовки списка, смены выбранного чата, потери scroll/focus или сдвига временной группы. Ошибка автогенерации не ломает отправленный разговор: после не более двух автоматических повторов применяется читаемое локализованное название из темы/типа первого сообщения, очищенное от разметки и кода; для сообщения только с кодом или файлами используются соответствующие краткие подписи. Временный «Новый чат» не становится постоянным названием из-за бесконечной загрузки.

Ручное переименование всегда имеет приоритет: `titleSource = manual` и версия проверяются атомарно перед записью результата генератора. Пока открыт inline input, фоновое название не заменяет введённый текст; после ручного сохранения поздний ответ отбрасывается. После отмены inline rename может отобразиться уже сохранённое автоматическое название. Генерация выполняется один раз на разговор, с ограниченными повторами в рамках одной операции; следующие сообщения, reload и смена модели не переименовывают его заново. Удалённый разговор не восстанавливается результатом фоновой задачи.

### Панель в свёрнутом виде: 64 px

В компактной панели сверху вниз остаются кнопка раскрытия, поиск, новый чат (карандаш), «Библиотека», «Плагины», «Запланировано» и «Обзор» для сохранения всей навигации. В самом низу остаётся только квадратная кнопка `≡` с accessible name и мгновенным tooltip «Меню», открывающая вверх тот же поповер служебных действий. Аватар, баланс и тариф остаются в правом верхнем углу страницы. Названия, дерево проектов и список истории скрыты; невидимые элементы исключены из tab order. Действия используют те же обработчики, что открытый сайдбар, и доступны на всех маршрутах workspace.

Каждая иконка имеет app-owned Tooltip уровня Radix/shadcn с намеренной задержкой открытия 0 ms по hover и keyboard focus; стандартный browser `title` не заменяет его. Tooltip показывает локализованное название и существующую горячую клавишу: поиск `Ctrl+K` / `⌘K`, новый чат `Ctrl+Shift+O` / `⌘⇧O`, раскрытие/сворачивание панели `Ctrl+Shift+S` / `⌘⇧S`. Tooltip и доступная подпись последней кнопки меняются между «Свернуть панель» и «Развернуть панель», shortcut остаётся тем же. Для действий без назначенного shortcut сочетание не выдумывается. Подсказка находится в portal вне обрезаемого overflow, учитывает края окна, закрывается по Escape/уходу hover/focus и не перехватывает нажатие. Accessible name остаётся у кнопки независимо от подсказки; на touch действие работает первым нажатием, название доступно вспомогательным технологиям.

Раскрытие возвращает сохранённые scroll position, раскрытые проекты и активную строку. На мобильном компактная desktop-полоска не отнимает место у чата: навигация открывается drawer, описанным выше.

Один компонент строки разговора используется в проектах, поиске, закреплённых, архиве и недавних. Справа при hover или keyboard focus появляются `…` и кнопка-булавка; у закреплённого разговора булавка остаётся видимой без hover. На touch меню и закрепление доступны без наведения. Нажатия на эти кнопки не открывают сам разговор. Булавка имеет `aria-pressed` и меняющуюся подпись «Закрепить» / «Открепить».

Контекстное меню сохраняет порядок и визуальные группы референса:

- переименовать;
- закрепить / открепить;
- разделитель, «Поділитися»;
- разделитель, архивировать / восстановить, удалить (danger);
- разделитель, «Перемістити до проєкту >»: список доступных проектов, «Вне проекта» для уже назначенного чата и «Новий проєкт».

«Поделиться» входит в полный реестр действий и каркас меню. До готовности публичного backend выбран вариант, разрешённый замечанием пользователя: пункт видим, помечен «В разработке», имеет `aria-disabled="true"` и доступное с клавиатуры/на touch пояснение. Включение действия управляется серверной capability `chatSharing`; при включении оно открывает диалог создания, копирования и отзыва ссылки. Подготовленный контракт требует отдельного разрешения доступа, явного выбора публикуемых сообщений и исключения скрытых инструкций, памяти и приватных файлов. Успешная публикация без backend не имитируется. Допустимость пункта меню не зависит от того, завершён ли этот backend; удалять его из каркаса нельзя.

Архив имеет отдельный доступный экран, удаление — явное подтверждение с названием объекта.

### Контекстное меню правой кнопкой

Строки чатов и проектов обрабатывают `onContextMenu`: правый клик предотвращает браузерное меню только на соответствующей строке и открывает её app-owned меню в координатах указателя. Это тот же реестр действий, что у кнопки `…`, с теми же disabled/capability-состояниями и авторизацией. Правый клик не выбирает другой чат, не открывает проект и не запускает rename сам по себе. Открытие следующего меню закрывает предыдущее, существующие tooltip/подменю не остаются поверх него.

Меню чата описано выше. Меню проекта содержит переименование прямо в строке, закрепление/открепление проекта внутри раздела «Проекты», новый чат, открытие инструкций/файлов/памяти и удаление. Закреплённые проекты располагаются вверху дерева проектов, не смешиваясь с блоком закреплённых **чатов**. Удаление проекта сохраняет оговорённое подтверждение и семантику сохранения разговоров.

`Shift+F10` / клавиша Context Menu вызывают то же меню у сфокусированной строки с привязкой к её границе. Координаты ограничиваются viewport с учётом размеров меню; portal исключает обрезание scroll-контейнером. Escape/клик вне закрывают меню и возвращают focus строке; скролл исходного списка закрывает меню у указателя, чтобы оно не осталось привязано к другой строке. В активном rename input сохраняется нативное меню копирования/вставки. Правый клик по остальной странице не перехватывается. На touch остаются явные кнопки `…`, без обязательного long press.

### Инлайн-переименование

«Змінити назву» закрывает контекстное меню и превращает название выбранной строки в активный `<input>` того же размера. Поле получает focus и выделенный текущий текст; модальное окно не открывается. Одновременно редактируется одна строка, на время ввода она не является кнопкой открытия разговора и не перетаскивается.

**F2** на сфокусированной строке чата или проекта немедленно запускает тот же inline rename, с выделением текущего названия. Shortcut использует сфокусированный объект, не случайный активный разговор; в composer, поиске, другом input/contenteditable и во время IME он не обрабатывается. Если rename уже открыт, повторный F2 не сбрасывает введённый текст. При обработке события предотвращается браузерное действие; кнопка меню и F2 используют один action и правила сохранения. Строки проектов имеют те же Enter/blur/Escape, ошибки и проверку версии, что чаты.

`Enter` сохраняет, клик вне поля/blur сохраняет, `Escape` отменяет и возвращает исходный текст без запроса. Окончание IME composition не считается командой сохранения. Enter с последующим blur отправляет только один PATCH; Escape подавляет следующий blur-save. Неизменённый текст не вызывает запрос. Пустое/состоящее из пробелов или слишком длинное название получает inline-ошибку и остаётся в поле для исправления; лимит соответствует DTO сервера.

После успешного сохранения название обновляется во всех местах: проекты, недавние, закреплённые, поиск и заголовок открытого чата. При сортировке по названию строка перемещается после завершения редактирования, сохраняя focus. Сетевая ошибка сохраняет введённый текст и показывает inline «Повторить» / «Отменить»; новая попытка не перекрывается поздним ответом прежней. Фоновое обновление истории не уничтожает input и выделение. Возврат focus после завершения идёт к строке, а не к закрытому пункту меню.

В строке заголовка «Нещодавні» слева стоит название, справа — три компактные кнопки: дополнительные действия `…`, фильтр/сортировка и быстрый новый чат с иконкой карандаша. Это постоянная точка управления списком, доступная также с клавиатуры и на touch; на desktop визуальная интенсивность может усиливаться при hover/focus.

Кнопка фильтра/сортировки открывает закреплённый у заголовка поповер:

- «Упорядкувати бічну панель >» → «За проєктами» / «В одному списку»;
- «Сортувати чати за >» → по последней активности / по названию;
- разделитель, подпись «Показувати», переключатель «Проєкти».

У текущего варианта видна галочка; состояния реализуются через menuitemradio/menuitemcheckbox. Подменю открываются нажатием и стрелкой вправо, закрываются влево/Escape; при нехватке места открываются с противоположной стороны. Изменение применяется сразу и сохраняется в настройках пользователя; ошибка сохранения возвращает прежнее значение и показывает повтор действия.

Кнопка `…` открывает меню дополнительных действий списка: «Архив» и «Открыть поиск». Карандаш создаёт новый разговор без проекта так же, как широкая кнопка шапки. Это три разных элемента вызова с собственными доступными именами, а не одно меню с неописанными кнопками.

Закреплённые чаты идут блоком **«Закріплені» сразу под деревом проектов и перед «Нещодавні»**, без календарных подзаголовков. Снизу блок отделяет тонкая полупрозрачная горизонтальная линия с отступами; он не сливается с группой «Сьогодні». При отсутствии закреплённых блок и разделитель скрываются. Если дерево проектов скрыто настройкой, закреплённые остаются перед недавними, а не исчезают вместе с ним. Вне общего блока закреплённый чат не дублируется; его принадлежность проекту показана вторичной подписью. Снятие pin возвращает строку в её проект/временную группу; pin не меняет время активности разговора.

В режиме «За проєктами» назначенные незакреплённые чаты находятся внутри проектов, остальные — в «Нещодавні»; в режиме «В одному списку» все незакреплённые неархивные чаты показаны в общем списке с отметкой проекта. Переключатель «Показувати: Проєкти» управляет видимостью отдельного дерева проектов, а не доступом модели к их контексту. Архивные не появляются в обычных разделах, но доступны через фильтр поиска. Для любого скрытия остаётся понятный путь возврата.

### Аккордеон проектов и локальная память

У каждого проекта отдельная кнопка-стрелка `›` / `⌵`, связанная с `aria-expanded` и `aria-controls`. Она раскрывает/сворачивает только его список, не открывает проектный overview и не меняет выбранный разговор. Название проекта отдельно открывает обзор. Несколько проектов могут быть раскрыты одновременно; стрелка поворачивается с общей анимацией 180–220 ms.

Состояние раскрытия сохраняется в localStorage по версии схемы и ID авторизованного пользователя, только как ID проектов и флаги, без названий/содержимого. Оно восстанавливается после reload, перехода между workspace-маршрутами и collapse/expand всей панели. Значения для удалённых/недоступных проектов отбрасываются после загрузки; при смене аккаунта читается его собственное состояние. Недоступный/повреждённый localStorage не мешает навигации — используется состояние текущего mount. Впервые загруженные проекты свёрнуты; только что созданный проект раскрывается автоматически. Открытие ранее выбранного разговора не перетирает явно сохранённое свёрнутое состояние.

У раскрытого проекта без чатов показывается компактная drop-зона с пунктирным контуром и подсказкой **«Перетягніть чат сюди або створіть новий»**, с отдельной кнопкой нового чата. Это реальная цель drag/drop, клавиатурное создание доступно без перетаскивания. Если все чаты проекта вынесены в блок закреплённых, вместо неверного «пусто» показана подсказка о закреплённых и действие нового чата. При loading рисуются skeleton-строки, при ошибке — повтор; эти состояния не подменяются пустой drop-зоной.

Автораскрытие по drag-hover временное: сохранённое состояние меняется при успешном drop или явном нажатии стрелки, отмена drag возвращает прежнее раскрытие. Пользовательское переключение имеет приоритет над восстановлением storage и поздними обновлениями списка.

### Временные группы «Нещодавні»

При сортировке по активности строки разделяются аккуратными локализованными подзаголовками «Сьогодні», «Вчора», «Попередні 7 днів», «Попередні 30 днів», затем названиями месяцев («Листопад», «Жовтень» и т. д.). У месяца другого года указан год. Пустые группы не рисуются, подзаголовок не является интерактивной строкой. При алфавитной сортировке временные группы отключены, чтобы порядок названий оставался последовательным. Внутри отдельных проектов сохраняется выбранная сортировка без обязательного повторения всех временных заголовков.

Группы определяются по `updatedAt` разговора, то есть по последней активности сообщений, а не по изменению названия, pin или projectId. При необходимости сервер выделяет отдельный `lastActivityAt`, чтобы PATCH метаданных не поднимал чат как новый ответ. В timezone пользователя, сохранённой IANA-строкой и первоначально определённой браузером, границы считаются от локальной полуночи календарными днями, с учётом DST:

- сегодня — текущая локальная дата;
- вчера — предыдущая дата;
- предыдущие 7 дней — оставшиеся даты от 2 до 7 дней назад включительно;
- предыдущие 30 дней — от 8 до 30 дней назад включительно;
- старше 30 дней — соответствующие календарные месяцы в обратном порядке.

Один разговор попадает ровно в одну группу; timezone не выводится из языка интерфейса. При переходе через полночь/возврате во вкладку группы обновляются без сетевого ожидания и потери scroll/focus. Пагинация продолжает существующую последнюю группу без повторного заголовка, дубли ID исключаются. Получение нового сообщения перемещает только затронутую строку; фоновые изменения не запускают каскад анимаций всего списка.

### Перетаскивание чатов в проекты

Строку из «Нещодавні» можно перетащить на видимую строку проекта. Drag начинается после движения указателя около 6 px, чтобы обычный клик открывал чат без задержки. Используется компактное превью названия; проект-цель получает мятный outline и мягкую подсветку, а hover над свёрнутым проектом около 500 ms раскрывает его. У верхней/нижней границы прокручиваемого списка работает автопрокрутка. Drop на вложенный элемент относится к его проекту, а не выполняется несколько раз из-за всплытия.

После drop используется существующий endpoint переноса, список оптимистично обновляется, при открытом разговоре обновляется active-project badge. Во время сохранения повторный перенос этого чата блокируется. Ошибка возвращает исходный проект, положение/группу строки и выделение, показывает повтор действия. Drop в тот же проект не делает запрос; отмена Escape или отпускание вне цели ничего не меняют. ID/владелец/права проверяются сервером независимо от drag payload.

Перетаскивание не меняет закрепление, архив или сортировку вручную. Оно недоступно для несохранённого черновика, строки в rename и неразрешённого пользователю проекта. В компактной панели дерево не появляется невидимой drop-зоной: для drag нужно раскрыть сайдбар. Меню «Перемістити до проєкту» остаётся равноправным способом с клавиатуры и на touch; drag не является единственным способом переноса. На touch scroll списка не блокируется обязательным long press.

Поиск выполняется на сервере по заголовкам и тексту сообщений текущего пользователя, с пагинацией, ограничением длины запроса и безопасными параметризованными запросами. Задержка ввода 300 ms, отмена устаревших запросов, мгновенная очистка. Запрос не попадает в URL, поскольку может содержать приватный текст разговора. Пустой запрос показывает недавние; нет результатов — отдельное состояние.

### Spotlight / Command Palette

Иконки поиска в обеих версиях сайдбара, `Ctrl+K` / `Cmd+K` и пункт поиска над историей открывают один общий Command Palette поверх текущего экрана. Это центрированный диалог шириной около 640 px с ограничением высоты по viewport, крупным input и прокручиваемыми результатами; поле поиска не встраивается в узкую колонку сайдбара. Подложка затемняет и слегка размывает весь workspace, блокирует взаимодействие с фоном. На телефоне palette адаптируется к доступной высоте и экранной клавиатуре.

Пустой запрос показывает команду нового чата и недавние разговоры. Результат содержит заголовок, проект/дату и короткий фрагмент совпавшего сообщения. Совпадения подсвечиваются `<mark>` в заголовке и фрагменте; текст и диапазоны приходят из серверного поиска и рендерятся безопасно, без вставки произвольного HTML. Поиск охватывает также не загруженные в sidebar разговоры; старое клонирование DOM-строк удаляется. Если совпадение находится в проекте или архиве, строка явно показывает эту область.

`ArrowDown` / `ArrowUp` меняют активный результат, `Enter` открывает его, `Escape` закрывает palette, `Tab` удерживает focus в диалоге. Input следует combobox/listbox-контракту с `aria-activedescendant`, индикатором загрузки и доступным количеством результатов; скринридер не озвучивает каждый токен ввода без ограничений. Footer показывает подсказки «↑↓ выбрать», «Enter открыть», «Esc закрыть». IME composition не запускает преждевременный поиск или открытие результата.

Клик вне диалога закрывает palette и возвращает focus вызвавшей кнопке/предыдущему элементу. Открытие диалога фокусирует input без таймера ожидания анимации; shortcut работает одинаково с раскрытой и компактной панелью. Кнопка очистки мгновенно отменяет прежний запрос и возвращает недавние. Устаревший ответ не заменяет новые результаты; ошибка остаётся внутри palette с повтором. Результат открывается по ID, без зависимости от наличия строки в DOM сайдбара; совпавшее сообщение выделяется после загрузки истории при доступном messageId.

Компонент переиспользует общий Dialog/Combobox либо поддерживаемый cmdk-подобный primitive. Конкретная библиотека выбирается по установленному стеку при реализации; добавление всего shadcn/ui не является условием выполнения дизайна. Единственный владелец palette исключает двойные listeners и одновременное открытие старого поиска.

## «Запланировано», «Плагины» и «Обзор»

Все три пункта входят в обязательный состав сайдбара. Отсутствие готового backend фиксируется как работа по соответствующей функции и состояние интерфейса, а не как основание вычеркнуть пункт из дизайна.

- **«Заплановано»** ведёт на `/scheduled`: список задач, время следующего запуска, состояния, создание/редактирование, пауза/возобновление и удаление. Задача хранит владельца, timezone, расписание, запрос, выбранную модель и необязательный проект; выполнение повторно проверяет доступ к проекту и кредитам. Рабочий backend должен обеспечить надёжный scheduler, защиту от повторного списания и историю запусков. Наличие BullMQ само по себе не доказывает готовность: текущие окружения различаются по поддержке workers. До подключения scheduler маршрут показывает явно обозначенное состояние недоступности и объяснение, форма не сообщает об успешном сохранении/запуске.
- **«Плагіни»** ведёт на `/plugins`: каталог поддерживаемых приложением интеграций, поиск, подключённые интеграции, описание разрешений, подключение/отключение и ошибки авторизации. Каталог и доступность приходят с сервера, приватные credentials остаются на backend. Это интеграции Genyxo, а не плагины среды Codex. При отсутствии настроенных интеграций показывается честное пустое состояние; подключение и выполнение инструмента не симулируются. Доступ к файлам/проектам выдаётся по явно выбранной области.
- **«Огляд»** открывает поповер у строки сайдбара. Реестр содержит категории из референса: карты, изображения, GPT/ассистенты, Sites и интеграции, включая Atlassian при её поддержке каталогом. Доступные записи ведут на соответствующий экран/интеграцию; изображения — на `/library?tab=images`. Для ещё не подключённых модулей сохраняется видимая запись с подписью «В разработке» и доступным пояснением, без фиктивного перехода или запуска. Escape закрывает поповер и возвращает focus к «Огляд».

Серверный реестр возможностей задаёт `available`, `unconfigured` или `planned` и причину. Для `unconfigured` экран показывает путь настройки, если он доступен этому пользователю; `planned` объясняет статус без обещания даты. Ни один обязательный пункт сайдбара не исчезает из-за отсутствия интеграции. Готовность каркаса и готовность scheduler/интеграций проверяются и сообщаются раздельно; полная функциональная готовность не объявляется при наличии только статусных экранов.

## `/plugins`: точная структура каталога и «Навички»

Account-блок остаётся в общей шапке справа сверху, как описано выше. Под ней собственная шапка `/plugins` имеет центрированные табы **«Плагіни» / «Навички»**, справа — иконку настроек `⚙` и кнопку **«Додати ⌵»**. Табы центрируются относительно области страницы, а не остатка места после кнопок; симметричные колонки/сетка исключают сдвиг центра. На narrow viewport actions переходят в отдельную строку без перекрытия tab bar. Переключение табов не меняет выбранный пункт sidebar: активным остаётся `/plugins`.

Ниже находится широкое поле **«Пошук плагінів»** во всю ширину контентной области, pill-формы, с лупой и кнопкой очистки. Поле имеет accessible label, поиск отменяет устаревшие запросы и сохраняет focus. Смена фильтра не показывает результаты прежнего запроса. Tab (`plugins`/`skills`), scope (`public`/`personal`) и view (`catalog`/`installed`) сохраняются в query `/plugins`; приватный текст поиска, credentials и редактируемые промпты в URL не попадают.

На вкладке «Плагіни» контент идёт в следующем порядке:

1. **«Встановлені >»** — горизонтальная лента подключённых сервисов: одинаковые круглые/скруглённые иконки, названия доступны подписями/tooltip, состояние подключения различимо. Лента имеет горизонтальный scroll с клавиатурой и доступные кнопки прокрутки при переполнении. Нажатие иконки открывает настройки соответствующего подключения; `>` открывает полный installed-view (`view=installed`) с действиями проверки/отключения. Заголовок не создаёт новую вкладку браузера. При пустой ленте видна короткая подсказка подключения без подставных иконок.
2. **«Публічні / Особисті»** — отдельные табы фильтра каталога, не замена верхней пары «Плагіни / Навички». Public показывает доступные каталожные интеграции; Personal — собственные API/вебхуки и персональные конфигурации пользователя. Фильтр меняет набор карточек, сохраняя installed-strip и доступ к «Додати».
3. **«Популярні >»** — каталог в **две колонки** на desktop, одну на узком экране. Карточка содержит крупную иконку слева, название, 1–2 строки описания в середине и компактное действие справа. `+` начинает подключение ещё не установленного сервиса; `…` открывает настройки подключённого/личного; `ℹ️` показывает разрешения. Назначение и доступность каждого действия явно заданы состоянием карточки, а tooltip/accessible label называет сервис. Клик по карточке открывает подробности, клик action не всплывает в открытие карточки. `>` раскрывает весь соответствующий каталог с пагинацией. «Популярные» берёт порядок из серверного каталога; числа установок или рейтинги не выдумываются.

Меню **«Додати ⌵»** на «Плагіни» содержит «Публичный плагин» (выбор реальной записи каталога и flow подключения) и «Собственный API / вебхук» (диалог имени, HTTPS endpoint, разрешённых действий и способа авторизации). Подключение публичного сервиса показывает разрешения до перехода в существующий OAuth/API-key flow. Секрет вводится masked, хранится зашифрованным на backend, не возвращается в каталог, URL или localStorage; в UI показывается только статус/замаскированная метка. Изменение/отзыв доступа выполняются сервером. Проверка webhook запускается явным действием с понятным результатом; endpoint и исходящие запросы проверяются против обращения к внутренним служебным адресам. В каталоге отображаются только поддерживаемые способы подключения, недоступный provider объясняет своё состояние.

`⚙` открывает настройки интеграций: управление подключениями, выданными разрешениями и доступной областью проектов. Account-настройки не дублируются в этой кнопке. У installed-strip, поиска, public/personal и сетки есть согласованные skeleton, empty, error/retry и reconnect-состояния. После установки/отключения лента и карточка обновляются из одного store без перезагрузки страницы. Наличие персонального ключа не делает конфигурацию публичной.

### Вкладка «Навички»: промпты, ассистенты, пресеты и роли

«Навички» — библиотека конфигураций **Genyxo**: системные промпты пользователя, ассистенты, пресеты и роли («Программист», «Копирайтер», «Аналитик»). Это сохранённые настройки ответов, не файлы навыков среды Codex и не автоматически исполняемый код. На этой вкладке сохраняются собственные поиск («Пошук навичок»), карточки и фильтр «Публічні / Особисті»: встроенные опубликованные шаблоны и приватные пользовательские настройки. Для неё installed-strip заменяется лентой сохранённых/выбранных навыков с соответствующей подписью; плагины не выдаются за навыки.

Карточка показывает название, роль/краткое описание и действие «Использовать» либо `…` для изменения/дублирования/удаления своего пресета. «Додати» открывает создание навыка: название, описание, текст инструкций, необязательная совместимая модель и область применения (текущий чат или выбранный проект). Промпт редактируется в обычной форме с сохранением/отменой и validation; примеры ролей должны быть настоящими доступными шаблонами. Публичный шаблон можно скопировать в личные, нельзя редактировать чужую запись.

«Использовать» применяет выбранный preset к текущему/новому разговору или явно выбранному проекту и возвращает в нужный чат. Первый выпуск поддерживает один активный preset на область; индивидуальный выбор чата имеет приоритет над default проекта. Возле composer виден применённый навык с действием снять/сменить; при смене модели навык сохраняется, а несовместимые настройки получают объяснение. Применение само по себе не отправляет prompt и не списывает кредиты. Редактирование шаблона не меняет незаметно существующие разговоры: хранится выбранная версия, обновление применяется явным действием.

`ChatContextService` получает ID/версию применённого навыка из серверного состояния, проверяет владельца/публичность и включает его инструкции как явно выбранную пользовательскую настройку во все поддерживаемые пути текстовых ответов. Они не отменяют системные правила приложения, изоляцию проектов или явно заданные инструкции проекта. Файлы/память остаются отдельными источниками данных. В метаданных ответа отражается применённый preset; удалённая/недоступная версия не заменяется случайным шаблоном. Ошибка загрузки навыка показывается до отправки с возможностью снять его.

## Библиотека: самостоятельный экран `/library`

Нажатие «Бібліотека» выполняет навигацию на `/library`. Экран доступен по прямой ссылке и после reload, использует ту же авторизованную оболочку и сайдбар с активным пунктом. Модальное окно или выпадающая панель не заменяют этот экран. Переход сохраняет черновик чата; возврат возвращает прежний разговор без повторного запуска генерации.

Верхняя строка содержит заголовок «Бібліотека», фильтры/сортировку, переключатель сетка/список, поиск с кнопкой очистки, «Створити» с меню и настройки отображения. Ниже находятся табы в порядке референса: «Рекомендоване», «Обране», «Папки», «Зображення», «Усі». На узком экране toolbar переносится, tab bar прокручивается горизонтально и сохраняет видимый focus.

- **Рекомендоване:** детерминированная подборка недавних и избранных материалов пользователя без выдуманных персональных рекомендаций или скрытой платной генерации.
- **Обране:** сохранённый на сервере признак избранного; действие доступно на карточке, в просмотре и в списке.
- **Папки:** создание, переименование, открытие и удаление папки; удаление папки сохраняет материалы вне папки. Перемещение имеет обычное меню, drag-and-drop может быть дополнительным способом.
- **Зображення:** только изображения с настоящими thumbnail, зарезервированными размерами, lazy loading и состоянием недоступного источника.
- **Усі:** все доступные пользователю документы, изображения и видео с пагинацией; тип материала явно различим.

Сетка карточек использует адаптивные колонки и естественные пропорции превью как в референсе, с контролируемым порядком DOM для клавиатуры. Список показывает те же действия и сведения. Документы имеют название и фрагмент/иконку формата; видео — постер и кнопку воспроизведения. Открытие карточки запускает просмотр с закрытием/Escape, скачиванием доступного оригинала и переходом в исходный чат при наличии доступа. Удаление, переименование, избранное и перемещение работают с тем же объектом во всех представлениях.

Поиск серверный, по названию и сохранённому тексту документа, с фильтрами типа/папки/избранного, сортировкой по дате или названию и отменой устаревших ответов. Выбранный tab, папка и сортировка сохраняются в URL; приватный текст поиска остаётся локальным и не записывается в URL. Режим сетка/список хранится в пользовательских настройках.

Меню «Створити»: документ, папка, загрузка файла. Документ создаётся в редактируемом приложением диалоге; папка — через форму названия; загрузка использует общий файловый workflow. Материалы из ответов моделей сохраняются существующим действием и появляются на `/library` после обновления данных. Новая генерация изображений требует отдельного явного отправления через существующий генератор с видимой моделью и стоимостью.

Состояния loading, первая пустая библиотека, пустая папка, нет результатов, ошибка, повтор и недоступный media URL различаются. Приватные файлы обслуживаются с проверкой владельца; чужой ID не открывается через прямую ссылку. Существующие ссылки провайдеров могут истечь: UI не обещает бессрочное хранение, пока файл не скопирован в контролируемое приватное хранилище приложения.

При первой загрузке и смене табов используются скелетоны формы будущих карточек/строк. При подгрузке следующей страницы они добавляются в конец списка; существующие карточки и положение прокрутки сохраняются. Известные aspect ratio/высоты резервируются до preview. Скелетоны мягко пульсируют, скрыты от скринридера; контейнер имеет `aria-busy` и краткий status. Быстрый ответ не задерживается ради демонстрации анимации. При reduced motion пульсация отключена. Ошибка заменяет placeholder на inline-повтор, а пустой результат — на соответствующее empty state; бесконечный spinner не подменяет эти состояния.

## Проекты и файлы

Проект содержит название, явные инструкции пользователя, файлы и собственную память. Список и содержимое всегда ограничены владельцем. Удаление проекта сохраняет разговоры, переводя их вне проекта, как в текущем сервисе; связанные файлы и память удаляются. Операция выполняется транзакционно и поясняется до подтверждения.

Файлы получают отдельные ID и записи `ChatProjectFile`: проект, владелец, имя, MIME, реальный размер, состояние обработки, извлечённый текст и версия. Это позволяет добавлять и удалять один файл без замены всего набора. Исходный файл сохраняется в приватном хранилище приложения за проверкой владельца; публичные URL не используются.

Перед добавлением проверяются фактический размер, допустимый формат и лимит проекта. Начальный предел: 5 файлов по 4 MiB, соответствующий нынешнему ограничению inline payload; ошибки показываются до отправки и повторно проверяются сервером. Для отдельного файла используются upload/progress/abort, а не один огромный JSON. Поддержка: текстовые форматы текущего продукта, PDF с текстовым слоем и DOCX после подключения парсера. Скан PDF без текста получает честное сообщение о необходимости OCR; OCR не входит в этот выпуск.

Состояния: загрузка, обработка, готов, ошибка с повтором, удаление. Файл с ошибкой не объявляется доступным модели. При миграции существующих JSON-вложений сохраняются доступные исходные данные и извлечённый текст; если исходник не сохранён текущим кодом, UI не предлагает скачать несуществующий оригинал.

Текст делится на фрагменты с устойчивыми ID и ссылкой на исходный файл. Первый выпуск использует поиск релевантных фрагментов по тексту и гарантированную выборку в пределах бюджета, без обязательной отдельной векторной БД. Индекс строится при обработке, а не при каждом ответе. UI показывает, какие файлы и фрагменты использованы, а также неполное включение контекста.

## Память: явные границы

Три разных уровня отображаются раздельно:

1. **История текущего чата.** Сообщения и существующая сводка длинной истории сохраняют продолжение разговора при смене модели.
2. **Память проекта.** Записи с важными фактами, решениями и предпочтениями, доступные всем разговорам только этого проекта.
3. **Личные предпочтения.** Отдельные записи пользователя, подключаемые к обычным чатам после явного включения. В изолированных проектах они по умолчанию не используются.

`ChatMemory` хранит владельца, область `project` или `user`, `projectId` для проектной записи, текст до 2 000 символов, источник (разговор/сообщение либо ручной ввод), даты и версию. Максимум 100 активных записей на область в первом выпуске. Пользователь может добавить, отредактировать, удалить запись и отключить применение памяти; отключение не удаляет данные.

В первом выпуске память пополняется явным действием «Запомнить» у сообщения или ручным вводом. Необязательное предложение модели сначала становится редактируемым черновиком; оно не сохраняется без действия пользователя. Это выбранное ограничение делает память проверяемой и предотвращает незаметное накопление ошибочных фактов. Автоматическое чтение всех прошлых чатов не обещается.

Удаление записи исключает её из следующих запросов и инвалидирует кеш. Удаление чата удаляет созданные из него записи памяти; UI предупреждает об этом. Ручные записи проекта сохраняются до их удаления или удаления проекта. Архив сохраняет данные, но не добавляет текст архивного чата автоматически в контекст других разговоров.

Перенос чата меняет проект для будущих ответов. Сохранённые факты не копируются в другой проект автоматически. История самого переносимого чата остаётся в нём, поэтому диалог подтверждения объясняет, что его прежние сообщения будут доступны при продолжении; старые проектные файлы и записи памяти заново не подмешиваются.

## Единый контекст моделей

`ChatContextService` становится единственным владельцем сборки контекста. Потоковый ответ, обычный ответ и альтернативная модель используют один контракт: системные правила приложения, инструкции проекта, выбранный навык/preset с проверенной версией, применимые записи памяти, релевантные фрагменты файлов, сводка текущего чата и последние сообщения с текущим запросом.

Авторизация проекта выводится из сохранённого разговора и текущего пользователя. Переданный клиентом `projectId` не позволяет сменить проект существующего разговора или получить чужой контекст; перенос выполняет отдельный endpoint. Все чтения, изменения, поиск и обработка источников проверяют владельца.

Инструкции проекта являются явно заданными настройками пользователя; содержимое файлов, извлечённые факты и цитаты сообщений маркируются как данные. Документ не может изменить системные правила или область доступа. Ссылки на источники берутся из реально выбранных записей, а не из произвольного текста ответа модели.

Контекст содержит отдельные структурированные блоки, а адаптеры OpenRouter и Gemini переводят их в поддерживаемые provider API роли. Одинаковая доступность контекста не гарантирует одинаковые ответы разных моделей. Модели изображений/видео используют только поддерживаемый ими prompt; интерфейс не обещает им текстовую память или чтение всех файлов.

Бюджет учитывает ограничение выбранной модели, резерв ответа и стоимость вложений. Если объём превышен, сервис отбирает релевантные источники и сворачивает старую историю, показывая это пользователю. Нельзя молча отбрасывать текущий запрос или представлять первые символы файла как полное прочтение. Неудача сводки имеет явное предупреждение об ограниченном контексте.

Ответ/SSE содержит метаданные контекста: ID проекта, ID/версия применённого навыка, ID и версии использованной памяти, источники файлов, факт ограничения контекста. Тексты приватной памяти не записываются в телеметрию. При редактировании проекта, файлов, памяти, выбранного preset и переносе разговора кеш инвалидируется с учётом нескольких экземпляров backend; локальный кеш не служит источником истины.

## Persistence и API

Расширить `Conversation`: `pinnedAt`, `archivedAt`, `titleSource` (`temporary` / `generated` / `fallback` / `manual`), `titleVersion`; обеспечить отдельную семантику времени активности сообщений (`lastActivityAt`, если `updatedAt` меняется при PATCH метаданных); добавить индексы по владельцу/архиву/активности и владельцу/проекту. У `ChatProject` добавить `pinnedAt` для порядка проектов внутри дерева. Стабильная cursor-пагинация использует время активности и ID, чтобы одинаковые timestamps не теряли строки. Настройки workspace хранить в `ChatWorkspacePreferences` по `userId`: группировка, сортировка, видимость проектов, timezone и режим библиотеки. Локально сохраняются раскрытые ID проектов/разделов и ширина панели по версии схемы и пользователю.

Операция автозаголовка хранит conversation/user ID, уникальный тип операции для разговора, статус, число попыток, исходную версию и даты. При миграции существующие названия помечаются как сохранённые пользователем для защиты от фонового переименования; генерация применяется к новым разговорам. Backend и канал событий не публикуют название чужому пользователю.

Каталог интеграций и подключения разделены: публичная запись сервиса описывает иконку, название, описание, возможности и способ подключения, `PluginConnection` хранит владельца, scope, provider/endpoint, разрешения, статус и ссылку на зашифрованные credentials. Каталог не отдаёт секреты. `ChatPreset` хранит владельца либо признак встроенного публичного шаблона, название, описание, инструкции, версию и совместимые параметры. Разговор/проект сохраняет выбранные ID/версии preset; source of truth — backend. Изменения этих контрактов входят в миграции и OpenAPI, не остаются только frontend mock.

Для библиотеки расширить `ChatLibraryItem`: `isFavorite`, `folderId`, `updatedAt`, сведения о приватном оригинале и preview при их наличии. Добавить `ChatLibraryFolder` с владельцем, названием и датами; первый выпуск использует один уровень папок. Сервер валидирует принадлежность папки и материала одному пользователю. Источник медиа не привязывается только к жёсткому списку из двух моделей: новые генераторы регистрируют результат через общий сервис библиотеки. Обратная индексация прежних материалов остаётся совместимым миграционным путём.

Существующие маршруты сохраняются совместимыми. Новый query-контракт списка добавляет пагинацию, поиск, область и сортировку; web переводится на него согласованно. DTO строго валидируют IDs, длины строк, enum, nullable-перенос и page size. Новые API:

- изменение pin/archive разговора и получение архивных;
- чтение/изменение настроек workspace;
- CRUD памяти с областью проекта или пользователя;
- добавление, статус, скачивание и удаление конкретного файла проекта;
- получение обзора проекта и метаданных реально использованного контекста.
- библиотека: пагинация/поиск/фильтры, изменение названия/избранного/папки материала, CRUD папок, создание документа, загрузка и авторизованное получение оригинала/preview;
- реестр возможностей навигации; список/управление запланированными задачами и история запусков при доступном scheduler; каталог/подключения плагинов при настроенном provider;
- контракт sharing capability и действий создания/отзыва ссылки; до реализации backend меню отображает согласованное состояние «В разработке».
- переименование с проверкой версии/устаревшего изменения; поисковые snippets/диапазоны подсветки и целевой messageId; идемпотентность первой отправки без отдельного создания пустого разговора.
- генерация/статус автозаголовка и versioned-событие `conversation.updated`; закрепление проектов внутри дерева, независимое от закрепления чатов.
- каталог/installed-view и private/public фильтры плагинов, подключение/проверка/отзыв API и webhook, публичные и личные версии навыков, CRUD/копирование preset и применение к чату/проекту.

Миграции добавляются новыми файлами. Уже существующие миграции не переписываются, поскольку неизвестно, были ли они выполнены. Перенос JSON-файлов идемпотентный и проверяемый по количеству; после него старые поля удаляются только отдельным последующим выпуском. Миграции проверяются на тестовой БД до production. Контракт OpenAPI и web types обновляются вместе.

## Владельцы UI и стиль

Общий React-владелец workspace shell и sidebar в FSD widgets используется маршрутами `/chat`, `/library`, `/scheduled` и `/plugins` через общий feature/API слой. Библиотека получает собственный FSD page/widget и переиспользуемые карточки материалов. DOM-контроллер чата предоставляет минимальные события выбора/создания/переноса и обновления данных; он не рисует второй список параллельно React. Выделение охватывает оболочку, маршруты workspace и оговорённые функции; transport, баланс, модель и сообщения не переписываются целиком.

### Active indicator и переключение маршрутов

Активный пункт `/chat`, `/library`, `/plugins` или `/scheduled` имеет мягкую серую заливку со скруглением и `aria-current="page"`; вкладка «Навички» и query-параметры сохраняют выделение `/plugins`. Логические группы «Проекты»/история не подменяют маршрутное выделение выбранного разговора. Навигация использует настоящие ссылки и поддерживает прямое открытие, Back/Forward и modifier-click.

В пределах текущего окна фон выделения — один общий визуальный indicator, плавно меняющий положение/размер за 180–220 ms, с сохранением текста/иконок на месте. Общая оболочка и sidebar сохраняют React identity при смене маршрута, не remountятся по pathname и не сбрасывают scroll, accordion, focus или черновик composer. Обновляется контентная область и выбранное состояние, переход не клонирует весь sidebar и не выполняет full-page reload. На исходном `/chat` без выбранного разговора подсвечен новый чат; при открытом разговоре выделена его строка, чтобы не показывать два конкурирующих активных chat-пункта.

Compact-режим использует ту же анимацию вокруг иконки. При collapse во время перехода indicator пересчитывает геометрию без прыжка, скрытый текущий чат не получает невидимый focus. При reduced motion положение меняется сразу или коротким opacity, без перемещения. Portal-поповеры закрываются перед переходом, их focus не восстанавливается в уже скрытую строку другого маршрута. Выбор active состояния происходит по текущему маршруту, без ожидания загрузки данных каталога.

Общие authored Menu/Dialog/Select, поля и уведомления переиспользуются или выделяются в `shared/ui`, если надёжного владельца ещё нет. Одно место управляет keyboard, focus, portal и закрытием по Escape. Источник дизайна — `DESIGN.md`, runtime chat tokens — существующий `chat.css` и стили страницы чата. При изменениях контракты и токены обновляются вместе.

Общие владельцы Tooltip, Command Palette, Inline Rename, Skeleton и drag-переноса также определяются до реализации. Инлайн-переименование и drag используют один API/store разговоров; библиотека и история используют согласованные skeleton/motion tokens. Локальные копии старого search modal и rename modal не сохраняются вторым независимым workflow.

Визуально: спокойный чёрно-графитовый фон, тонкие границы, мягкие состояния hover, светлый текст и существующий мятный акцент Genyxo. Читабельная типографика и компактные строки важнее декора. Активный чат различим формой и фоном. Длинные названия обрезаются в строке, полное название доступно. Light theme поддерживает те же состояния.

Поповеры «Огляд», настроек списка, подменю и контекстного меню используют общий glass token: `backdrop-filter: blur(12px)`, графитовую заливку `rgba(38, 38, 38, 0.88)` и `border: 1px solid rgba(255, 255, 255, 0.08)`, мягкую тень и одинаковые радиусы. Блюр применяется к фону, текст остаётся резким. При отсутствии backdrop-filter остаётся непрозрачная графитовая подложка; light theme использует соответствующие контрастные токены. Palette наследует язык этих поверхностей, а её overlay использует отдельный токен затемнения/размытия. Меню находятся в portal и не обрезаются scrollbar-контейнером.

Все новые подписи, ошибки, aria labels и пустые состояния проходят через существующую i18n для en/uk/es/de/fr. Язык сообщения пользователя не меняет языковую политику продукта автоматически.

## Анимации и доступность

- Наведение и нажатие: 120–160 ms, мягкая подсветка и небольшое сжатие иконки.
- Переключение выбранной строки и раскрытие проекта: 180–220 ms, без перезапуска анимации всего списка после каждого токена.
- Меню: opacity/translate на 140–180 ms; позиционирование учитывает края окна и прокрутку.
- Desktop collapse и mobile drawer: 240–300 ms; движение соседнего содержимого не ломает ширину composer и не сбрасывает его фокус.
- Pin/archive/move: немедленное состояние действия, короткое перемещение/исчезновение строки; ошибка откатывает оптимистичное изменение и остаётся доступной для повтора.
- Dialog: 180–220 ms. Нет искусственных задержек запросов, конфетти или постоянного свечения вокруг текста.
- Панель «Огляд», меню заголовка, вложенные меню и меню чата используют одинаковые motion tokens. Табы библиотеки имеют плавный индикатор активного состояния; смена сетки/списка и фильтров сохраняет focus и не задерживает отображение данных. Preview мягко появляется после загрузки без сдвига карточек.
- Тултипы появляются без задержки; palette открывается через opacity/короткое смещение за 160–200 ms, но input доступен сразу. Drop-цель плавно подсвечивается за 120–160 ms; отмена/ошибка возвращает строку без потери её состояния. Пульсация Skeleton медленная и спокойная, без яркой бегущей полосы.
- `prefers-reduced-motion` отключает перемещение и масштабирование, сохраняя мгновенную обратную связь. На touch нет функций, доступных только при hover.

Навигация использует кнопки/ссылки с доступными именами, видимый focus, `aria-expanded` и `aria-current`. Меню управляется стрелками/Home/End/Escape; диалоги удерживают focus, делают фон inert и возвращают focus к вызывавшей кнопке. Закрытый sidebar не остаётся в tab order. Mobile overlay блокирует прокрутку фона и учитывает safe area. Новый чат — Ctrl/Cmd+Shift+O, поиск — Ctrl/Cmd+K, свернуть/развернуть sidebar — **Ctrl/Cmd+Shift+S**, inline rename сфокусированной строки — **F2**. Один владелец shortcuts регистрируется на workspace mount и освобождает listeners при unmount; комбинации не срабатывают дважды из старых контроллеров. Ctrl/Cmd+Shift+S использует то же действие, что кнопка collapse, плавно переключает desktop 280/64 px, сохраняет composer/focus и не ждёт сети; на mobile открывает/закрывает drawer. Во время IME и поверх блокирующего modal/drawer-form глобальное переключение не выполняется. `preventDefault` применяется только для обработанной комбинации; обычный текстовый ввод не перехватывается.

Scrollbar поверхностей workspace тонкий: 5 px в WebKit/Blink, `scrollbar-width: thin` в движках со стандартным API; track прозрачный, цвет thumb в тёмной теме `rgba(255, 255, 255, 0.15)`. Скролл-контейнеры используют `scrollbar-gutter: stable`, чтобы появление thumb не сдвигало строки и карточки. В покое thumb прозрачен, при прокрутке колесом/трекпадом/касанием показывается и через 700 ms после последнего scroll мягко исчезает; во время захвата thumb остаётся видимым. При управлении клавиатурой и focus внутри scroll-region thumb также становится видимым, forced-colors сохраняет системные цвета. Сам скроллбар не удаляется через `display: none` или нулевую ширину. Light theme имеет свой контрастный thumb. Один CSS/scroll-activity owner обслуживает sidebar, palette и библиотеку и освобождает listeners/timers при unmount.

История при начальной загрузке показывает skeleton-строки, при подгрузке старых чатов — skeleton-строки в конце существующих групп. Размер строки и заголовка группы заранее зарезервирован; skeleton не получает focus и не выглядит настоящим кликабельным разговором. `aria-busy` и status сообщают о загрузке. UI не прыгает при загрузке; для empty/loading/error предусмотрены стабильные размеры. Критические ошибки показаны рядом с действием, toast не является их единственной копией.

Backend unit/integration:

- account-блок с аватаром/балансом/тарифом находится сверху справа; в footer раскрытой панели только «≡ Меню», в 64 px только квадратная `≡` с мгновенным tooltip; одинаковый поповер открывается вверх и сохраняет служебные действия;
- первый ответ → асинхронное название из 3–5 слов без ожидания основного ответа, refresh/reconnect, ошибка/fallback, ручное переименование во время задачи, удаление/смена чата до события и отсутствие потери focus/scroll;
- правый клик по чату/проекту и Shift+F10 открывают тот же menu registry, проверены координаты у краёв, отсутствие выбора/открытия по right click, закрытие по scroll, сохранение native context menu в input и вне строк;
- стрелки проектов независимы от открытия overview, localStorage восстанавливается после reload и разделён по аккаунтам; повреждённый storage/удалённые ID, empty drop-zone и временное drag-hover раскрытие проверены;
- точный порядок проектов/«Закріплені»/«Нещодавні», разделитель под закреплёнными, отсутствие временных групп и дублей в pinned-блоке, скрытые проекты и снятие pin.
- `/plugins`: центральные табы, settings/add справа, pill-поиск, installed-strip с overflow/полным view, отдельные public/personal фильтры, двухколоночные карточки `+/…/ℹ️`, mobile одна колонка, установка/отключение и skeleton/error/retry;
- «Навички»: создание/копирование/редактирование/удаление, применение к чату/проекту без отправки, badge и снятие, сохранение версии после смены модели, отдельный поиск и ошибки недоступности;
- `+` рядом с «Проєкти» открывает создание напрямую при пустом/свёрнутом списке, файлы/инструкции сохраняются, отмена не создаёт пустой проект, успех раскрывает новый;
- F2 работает на строках чата/проекта, не вмешивается в composer/input/IME; Ctrl/Cmd+Shift+S работает один раз, tooltip содержит shortcut в обоих состояниях, narrow/mobile и сохранение focus проверены;
- переходы `/chat ↔ /library ↔ /plugins ↔ /scheduled`, query табов, Back/Forward и direct load: active indicator соответствует маршруту, sidebar не remountится и сохраняет scroll/accordion/draft, reduced motion и collapse во время перехода не дают скачка.
